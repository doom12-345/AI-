# AI抖音游戏情绪文案生成器

> 玩抖音小游戏的人有个很具体的痛点：玩完一肚子情绪，想吐槽、想发泄、想炫耀，
> 但他不会写、懒得写，或者怕写出来没人理。
>
> 这是个 PC 端小工具：你打一句大白话，比如「羊了个羊第二关玩了20把没过」，
> 它给你三段 —— 一句损友式吐槽、一条 60 字以内能直接发的文案、2~3 个话题标签。
> 点一下复制就能发。

一个放在电脑上的小窗口，把"情绪"翻译成"能发出去的话"。

---

## 它是什么

**做：** 把情绪翻译成"能发出去的内容"。

**它解决的不是"不会玩游戏"，而是"有情绪、但不知道怎么写出来"。**

用户此刻只有情绪，没有表达欲。所以这个工具的输入门槛被压到最低 —— 一句话、随便说，
不需要想"该怎么提问"；输出也是现成的 —— 可直接发、自带话题标签、点一下复制。

### 为什么要单独做一个，而不是直接用通用 AI

| 维度 | 通用 AI | 这个工具 |
|---|---|---|
| 门槛 | 得先想清楚怎么提问，可他此刻只有情绪 | 打一句大白话就够 |
| 结构 | 给一段话 | 三段：吐槽 / 可发文案 / 话题标签，并标明哪段是给自己的、哪段是发出去的 |
| 边界 | 会顺手给攻略，也可能顺着他说"你确实有点菜" | 不给攻略、不评价用户，两条都写死在机制里 |

后两条都会当场毁掉体验 —— 一个想发泄的人，最不想收到"攻略"和"评判"。

---

## 它不是什么（产品边界）

这块是刻意划出来的，每条都有理由：

| 不做 | 为什么 |
|---|---|
| 不给攻略 | 给了攻略，它就从"情绪出口"变成"工具书"，而且用户发出去的评论也没人愿意接 |
| 不读游戏状态 | 需要接入游戏，成本和合规风险都跟收益不成比例 |
| 不识别截图 | 同上，还会把"随手一句"变成"要上传图片" |
| 不自动发布 | 发布是不可逆动作，必须由用户自己确认 |
| 不做战绩记录 | 他要的是"这一条能发"，不是一份数据报表 |
| 绝不骂用户 | 他已经在情绪里了，再被冒犯一次就直接卸载 |
| 不碰敏感 / 引战 | 发出去的是他的账号，风险不能转嫁给他 |

其中第 6 条有个容易做错的细节：
**允许用户自己损自己（玩梗式自嘲），AI 本人绝不许说用户半个不字。**
"我菜我认了"是评论区的灵魂，但"AI 说你菜"就是冒犯 —— 这两件事看着像，本质完全不同。

## 输出长什么样

三段，各有分工：

| 字段 | 名称 | 规格 | 承担什么 |
|---|---|---|---|
| `roast` | 损友吐槽 | 一句话，阴阳、有梗、有画面感 | 情绪价值（说给用户听的，不用发） |
| `copy` | 可发文案 | 第一人称、口语短句，30~55 字最佳，**上限 60 字**（含标点） | 行动价值（复制这段去发） |
| `标签` | 话题 | 2~3 个，`#` 开头、每个不超过 8 字、不带空格 | 被看见的概率 |

模型被要求只输出一个 JSON 对象：

```json
{"roast": "...", "copy": "...", "tags": ["#...", "#..."]}
```

60 字的限制不是随口定的：抖音评论超过一定长度就没人看完。界面上会实时显示
`0 / 60 字`，超了会提示"超了，点「换一版」"。

### 一个真实样例

> 输入：`羊了个羊第二关玩了20把没过，气得我想砸手机`
>
> - **损友吐槽**：玩20把还卡在第二关，这游戏是来挑战你怒气的。
> - **可发文案**：20把没过第二关，我感觉我的手指都要气断了。这关，它赢了。（29字）
> - **话题**：`#羊了个羊` `#第二关有毒` `#气到冒烟`

（以上为模型真实输出，非示意。更多样例见 `文案样例.txt`，里面还附了改版前后的逐条对比。）

## 快速开始

### 方式一：直接用打包好的程序（推荐，不需要装任何东西）

去本仓库的 **发布** 页面下载绿色版压缩包，解压后双击
`AI抖音游戏情绪文案生成器.exe` 即可。

> ⚠️ 绿色版必须**整个文件夹一起保留**，不能只把 exe 单独拖出来 ——
> 那样会打不开。要挪位置就整个文件夹一起挪。

### 方式二：双击启动器（电脑里已装过 Python）

双击项目目录里的：

```
启动文案生成器.bat
```

启动器会自动按顺序探测本机 Python（已知安装路径 → Windows 自带 `py` 启动器 →
常见安装目录 → 系统 PATH），优先用 `pythonw` 无黑框启动；全部失败时会写一个
`启动日志.txt` 并给出中文指引，而不是一闪而过。

### 方式三：从源码运行

```bash
python app.py
```

> 注意：直接双击 `app.py` 是不会开窗口的 —— 那是程序本体。
> 源码模式请用上面的命令，或双击 `启动文案生成器.bat`。

### 配置 API Key（必做）

程序本身不带 Key，需要你用自己的智谱开放平台账号。

1. 到 [open.bigmodel.cn](https://open.bigmodel.cn) 控制台 → 「API Keys」创建一个 Key；
2. 把 `config.example.json` 复制一份，**改名为 `config.json`**；
3. 打开它，把 `api_key` 换成你自己的 Key。

```json
{
  "api_key": "你的 Key 填这里",
  "base_url": "https://open.bigmodel.cn/api/paas/v4",
  "model": "glm-4-flash-250414",
  "fallback_model": "glm-4.5-flash",
  "timeout": 60
}
```

- 源码 / 启动器模式：`config.json` 放在 `app.py` 同目录；
- exe 模式：`config.json` 放在 exe 同目录。

没有 `config.json` 时，首次启动会正常弹出设置向导，可以直接在界面里填 Key。
换模型只改 `model` 这一行即可。

> 🔒 `config.json` 已被 `.gitignore` 排除，**请永远不要把它提交到仓库**。

### 自检入口（开发用）

```bash
python app.py --selftest   # 功能自检，结果写入 _自检结果.txt
python app.py --uitest     # 界面链路自检，结果写入 _uitest.txt
```

打包后的 exe 同样支持这两个参数，结果写在 exe 同目录。

## 技术实现

- **Python + tkinter 单文件桌面程序，零第三方依赖** —— 只用标准库
  （`urllib.request` 发请求，`json` / `re` / `threading` / `queue` 处理数据）。
  没有 `requests`、没有 GUI 框架，拿到源码配一个 Python 就能跑。
- **AI 服务**：智谱开放平台，`https://open.bigmodel.cn/api/paas/v4/chat/completions`，
  `Authorization: Bearer <API_KEY>`。
- **模型**：默认 `glm-4-flash-250414`（免费档），备胎 `glm-4.5-flash`，主模型失败自动切换。
- **结构化输出**：请求带 `response_format: {"type": "json_object"}`，
  并关闭思考模式（`thinking: {"type": "disabled"}`）。
- **解析层 5 层降级**：剥 ``` 围栏 → `json.loads` → 正则截取 `{...}` →
  识别中文字段标记 → 原文兜底。**永不白屏、永不把异常抛给用户。**
- **多线程**：子线程只往 `queue` 里投递结果，主线程用 `root.after(100, poll)` 取回，
  worker 内部不触碰任何控件（避免 tkinter 跨线程崩溃）。
- **剪贴板**：`clipboard_clear()` → `clipboard_append()` → `root.update()`，
  窗口常驻不销毁 —— 否则剪贴板内容会随进程退出而丢失。

## 质量与安全机制

这是投入时间最多的部分。核心思路：**不把安全寄托在"模型愿意听话"上。**

### 三层防线

1. **提示词约束** —— 红线写死在 system prompt 的最高优先级位置；
2. **代码层二次检测** —— 拿到模型输出后再用词表和规则检查一遍；
3. **越界自动重生成** —— 检测到越界就重新生成，最多 3 次；3 次仍越界也返回结果，不让用户面对空白。

### 检测维度

辱骂 / 自弃词、攻略鸡汤词、拆台式否定（"不是你强，是游戏给面子"）、评判用户水平、
照抄提示词、给游戏说好话，以及**事实反转** —— 用户说"没过"，文案却写成"过了"，
这种发出去会闹笑话。

### 两个关键取舍

**① 宁可误报，绝不漏报。**
误报的代价只是多花两秒重生成一次；漏报的代价是把不该给用户看的内容给了他。

**② 用户主动要求越界时，从请求源头剥离。**
用户在补充框里写"狠狠地骂我"，程序不是事后纠正，而是**把这句话从请求里删掉再发给模型** ——
模型根本看不到这个诉求，也就不会迎合、不会绕道自嘲，而是正常帮用户骂游戏。
这比事后补救可靠得多。

### 一条走偏过又纠正回来的规则

最初为了防止"AI 骂用户"，把"自我贬低"也列进了违规词。
结果模型只剩"安慰"这条最安全的路可走 —— 8 条输出里有 6 条在写
"不是你的问题，是游戏太坑了"，整个产品的性格从"损友"变成了"陪聊"。

修正方式是明确区分：**自嘲（用户损自己）允许，被贬低（AI 损用户）禁止**，
并明令禁止"开脱 / 安慰"句式。
**一条过严的规则，会把产品的性格整个改掉** —— 这是这个项目里最值钱的一次教训。

## 已知限制（如实写出）

- **免费小模型做不到 100% 不跑偏。** 偶尔有事实口误，例如用户说"没过"它写成"过了"。
  已加代码层拦截，但只能拦住大部分，挡不住全部；点「换一版」通常能刷掉。
- **文案质量有波动。** 有的很妙，有的偏绕。这是模型水平的上限，不是 bug。
- **敏感内容过滤是"概率性降低 + 后置检测"，不是 100% 语义拦截。**
- **打包出的 exe 没有数字签名。** 个别电脑（尤其装了 360 的）首次运行会弹安全提示，
  需要手动点"允许/继续"。所有自行打包的小程序都有这个问题，不是本工具特有的。
- **单文件版跑自检时耗时异常长**（221 秒，而文件夹版只要 32 秒）。
  怀疑与"每次解压 27MB + 安全软件扫描"有关，**但尚未证实**，如实标注。

### 关于本文档中的数据

文中提到的体积、启动耗时、测试用例条数等，均为**本机实测**记录。

需要明确的是：**这些是功能与安全测试（验证"输出不越界""异常不崩"），
不是需求验证。** 本项目目前没有真实用户数据 ——
发布率、回复率、留存率一个都没有，所以这里也不会出现任何此类数字。
